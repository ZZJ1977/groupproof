# 清理演示数据后的工作区功能恢复

## 用户要求与问题

删除现有模拟记录，保留原有业务功能、入口和操作流程。上一轮将默认真实数据与通用页面拦截一起启用，导致首页缺少创建/加入按钮、旧课程及项目流程无法操作，本次修复这一回归。

## 实现边界

- 保持 Staging / Production 真实 API 与空数据初始状态，不恢复演示课程、项目、任务或本地假成功写入。
- 复用现有 UI、路由、权限和业务规则；选择性整合 B 分支已经实现的学生流程，不整体合并分支、不替换当前 A/C/D 模块和认证改动。
- 首页标题区与空状态保留“创建项目”“加入课程”。创建入口通过 `/courses?intent=create-project` 选择课程；没有课程时引导加入课程。
- 加入课程：`/courses/join` 邀请码预览 → 确认课程 → 加入或等待审核 → 小组列表。
- 课程小组：查看、创建、加入、管理与组长转让；课程项目：当前小组组长创建 → 初始化 → 需求 → 计划 → 任务。
- 保留项目总览、里程碑、退出小组及成员变更操作。真实服务拒绝或外部依赖未配置时显示准确反馈，不能生成模拟结果。
- 现有课程公开范围、学校邮箱、成员关系、人数/截止时间、乐观锁和幂等约束由后端实施。

## 数据与迁移

只新增 B 模块数据表、索引及必要字段，迁移接在 develop 当前 head 后。测试数据仅放隔离数据库 schema 或测试接口，不向用户的 Staging 账户添加演示记录。

## 验收

1. 零课程/项目时按钮可见、可点击，有明确下一步；移动端可用。
2. 输入邀请码、预览、加入、组队、创建项目及后续手工需求/任务流程调用真实 API。
3. 无权、无效邀请码、过期/结束课程、非组长、重复写入等有明确错误且不越权。
4. 首页/课程列表在成功操作后更新，模拟记录与旧缓存不会重新出现。
5. 运行前端类型/构建/路由检查、隔离浏览器回归与 B 模块 PostgreSQL 测试；部署后核验实际入口。

实际验证结果见 FRONTEND_STATUS.md 的同日恢复记录。浏览器覆盖 47 个场景，包含桌面/390px 入口、邀请码、组队、创建规则、需求与任务操作及演示缓存隔离。首次并发执行构建时出现代理编译等待和一次开发脚本解析失败；预热真实会话代理、停止并发构建后定向重跑均通过。另一失败来自旧文案断言，已与当前空状态一致。

后端真实 PostgreSQL 用例与迁移往返通过。课程项目创建读取 D 已发布规则与模板，校验人数、组长与版本；写入在课程/项目/小组锁内重新检查权限，异步分析也在保存结果前重检。材料上传的自动正文提取提供方尚未接通，保留真实不可用反馈；手工文本录入可用。
