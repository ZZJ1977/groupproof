## 1. 产品决策

提供可独立工作的“邮箱验证 → 设置用户名和密码 → 创建账户”入口。Google 是可选登录方式，未启用或不可用时不影响邮箱注册和密码登录。

邮箱验证码用于首次证明登录邮箱归属，后续以邮箱/用户名和密码登录。首期不增加“每次都发验证码的免密登录”，避免邮件瞬时故障成为所有用户的登录阻断因素。

复用现有 PostgreSQL 中的 `users`、`password_credentials`、会话、学校邮箱绑定与教师审核表。新增注册前验证事务及必要字段；不引入第二个用户库，不复制第二套权限体系。

必须区分两个完成节点：

1. **账户创建完成**：登录邮箱已验证、密码已设置，可进入受限个人中心。
2. **平台注册完成**：必填资料、学校邮箱验证及所需教师审核全部满足，服务端才开放业务访问；访问具体课程/项目仍需资源权限。

普通邮箱（如 QQ）可作登录邮箱；学校邮箱只用于学校资格核验，也可由用户选作登录邮箱。两者不是同一概念。验证邮箱控制权也不等于证明姓名、学号或任职信息真实。邮箱归属验证的基本要求参考 [OWASP Email Validation and Verification](https://cheatsheetseries.owasp.org/cheatsheets/Email_Validation_and_Verification_Cheat_Sheet.html#email-ownership-verification)。

## 2. 用户流程、页面与界面约定

### 2.1 注册主流程

```text
登录页：邮箱/用户名 + 密码；注册账号；忘记密码；可选 Google；语言选择
  ↓ 点击注册
步骤 1：填写登录邮箱 → 请求验证码
  ↓ 真实发件服务接受请求
步骤 2：输入邮箱收到的验证码 → 服务端验证
  ↓ 取得绑定本次注册事务的限时建档资格
步骤 3：设置用户名、密码、确认密码 → 服务端事务创建账户
  ↓ 签发 onboarding 会话
个人中心：填写资料 → 学校邮箱验证 → 教师申请审核（仅教师）
  ↓ 服务端根据当前事实判定 active
进入课程/项目，并逐资源校验权限
```

步骤 1–2 属于公开注册流程，不创建永久用户，不保存用户密码，不占用用户名；步骤 3 才建立用户和密码凭据。避免他人提前用受害者邮箱与攻击者密码创建账户，等待受害者完成验证。

### 2.2 页面地图

| 入口/页面 | 身份条件 | 主要任务及成功去向 |
|---|---|---|
| `/login` 注册弹窗 | 未登录 | 在同一弹窗完成邮箱、验证码、密码三步，成功进入个人中心 |
| `/login` 密码登录 | 未登录 | 按后端 nextAction 进入个人中心或授权业务页 |
| `/login` 忘记密码弹窗 | 未登录 | 输入登录邮箱，获得统一的安全反馈 |
| `/reset-password`（新增公开页） | 有效恢复凭据；没有业务会话也能打开 | 输入新密码，成功后返回登录页，不自动获得 full 会话 |
| 既有个人中心注册页 | onboarding/full | 完成资料与学校验证；显示登录邮箱与学校邮箱的独立状态 |
| 个人中心账户安全区 | 已认证；敏感操作需要近期重新认证 | 修改密码、验证历史登录邮箱；后续支持登录方式绑定 |

新增页面须同步既有路由映射及匿名访问检查。保持登录页没有“完善个人资料”“验证学校邮箱”快捷通行按钮；注册弹窗内的登录邮箱验证是注册步骤。

### 2.3 线框与反馈

- 沿用现有颜色、字号、按钮、Dialog、表单组件，不进行视觉重做。标题显示“注册账号 · 第 1/3 步”等清晰进度。
- 步骤1仅显示登录邮箱、“发送验证码”、返回登录；说明“可使用常用邮箱，学校身份将在个人中心验证”。
- 步骤2显示脱敏收件地址、验证码输入框、服务端倒计时、“重新发送”“修改邮箱”。修改邮箱使当前验证资格失效。
- 步骤3显示已验证邮箱、用户名、密码、确认密码；邮箱不可偷偷改写。主按钮“创建账户并继续”。
- 账户建档后显示“账户已创建，请继续完成个人资料与学校验证”；只有通过全部准入条件才显示“可以进入工作区”。
- 每步有提交中、成功、校验错误、过期、限流、网络中断、邮件故障状态。验证码或密码不写 localStorage，不上传埋点；关闭弹窗后清理密码。
- 邮件故障显示“验证码暂未发送成功，请重试”；服务端已接受发送但收件未到时显示查阅垃圾邮件、确认地址及倒计时重发提示。不得在提交 SMTP 前显示“已发送成功”。
- 失败保留非敏感输入；错误可被读屏播报，并聚焦相关字段。支持验证码整体粘贴、密码管理器、密码显示切换、键盘前后操作。
- 简体、繁体、英文覆盖全部新文案、邮件模板和错误；切换语言不丢失当前注册进度。

## 3. 状态与权限

注册前状态由独立事务记录：`awaiting_code → email_verified → completed`；失败旁路包括 `expired`、`invalidated`。发送状态单独记录 `pending / accepted / failed / unknown`，不能把“发件请求被接受”当作邮箱已验证。

| 状态 | 可执行操作 | 不得执行的操作 |
|---|---|---|
| 匿名/注册前验证中 | 注册、登录、请求恢复；访问本人绑定的注册事务 | 获取用户业务资料或业务数据 |
| 登录邮箱验证成功，未建档 | 在短期资格内完成本次账户创建 | 建立角色、课程、项目关系；调用业务 API |
| 新建账户，onboarding | 个人资料、学校邮箱验证、教师申请、退出 | 读取/修改课程、项目、证据、文件等业务数据 |
| 历史密码凭据尚未验证登录邮箱 | 通过原密码验证后进入登录邮箱补验及既有受限个人中心 | 通过该未验证凭据获得 full 业务权限；用未验证邮箱找回旧账户 |
| active | 按资源权限访问业务 | 越权读取其他项目或自助授予教师/管理员 |
| disabled | 必要状态提示与退出，恢复操作按现有停用策略处理 | 通过注册、重置、绑定或重新验证解除停用 |

新账户不需要先创建 `login_email_required` 的永久状态，因为创建前已验证。历史密码账户需要补验状态：可增加 `login_email_required` 的 nextAction，或在 DTO 中独立表达凭据验证要求；服务端会话签发和逐请求门禁都必须执行，前后端语义一致。

多登录方式时，学校资格仍是账户层事实；“当前会话是否通过可信登录方式认证”是会话层事实。已验证 Google 身份的既有用户不应仅因另一条未验证密码凭据而被无条件停用；但未验证密码通道不能借该账户的 active 状态取得 full 会话。以明确的 `auth_method`、凭据验证依据和当前版本判定。

后端每次请求校验当前账户状态、会话有效性、注册资格与资源权限。客户端传来的 `role`、`verified`、`active`、`user_id` 不成为授权依据。`verificationBasis` 按实际方式记录；当前统一输出 `google_auth` 的逻辑须更正，不能把密码认证伪装为 Google 认证。

## 4. 数据模型与一致性

以下是逻辑字段要求，优先复用现有等价结构；迁移版本号由执行时实际 head 决定。

| 实体 | 变更与关键字段 | 约束/用途 |
|---|---|---|
| `users` | 沿用主键、用户名、账户状态、资料与角色 | 用户名按既有策略唯一；角色来自受控服务端逻辑 |
| `password_credentials` | 增加 `login_email_verified_at`、验证依据引用、凭据版本；保留邮箱原值/比较值、hash/算法、改密时间 | 一个用户最多一条本地密码凭据；登录邮箱比较值唯一；不得把历史行自动标记为已验证 |
| `pre_registration_requests`（新增） | 高熵 ID、邮箱及比较值、locale、浏览器事务令牌摘要、验证码 HMAC、generation、期限、错误次数、发送状态、验证码消费时间、建档资格摘要/期限、完成时间、结果 user_id | 注册前不依赖 users 外键；验证码与建档资格均为一次性；可按事务锁实现原子消费 |
| `email_challenges` | 学校验证继续使用；恢复密码可增加独立 purpose 与安全随机令牌摘要、凭据版本 | 当前 user_id 非空，不能直接拿它存不存在用户的注册前挑战；必须隔离用途 |
| `sessions` | 复用现有存储，补全登录方式及验证依据/凭据版本（如已有则复用） | onboarding/full 权限由服务端计算；改密、停用和恢复时可撤销 |
| 审计与限流记录 | 记录请求关联标识、操作类型、成功/失败、脱敏主体、时间与必要版本 | 不记录密码、验证码、恢复凭据或邮件正文；多进程共享限流事实 |

邮箱处理保持注册、登录、恢复、绑定一致。保存原始地址；使用成熟校验库；域名大小写与国际化域名按统一策略处理。现有实现对登录邮箱作不区分大小写比较，迁移前审计这一策略与历史数据，不在本次中悄悄改变比较规则。不要擅自删除 Gmail 点号、`+` 后缀或合并“看起来相同”的地址；数据库冲突不自动转移账户。依据参考 [OWASP 邮箱规范化建议](https://cheatsheetseries.owasp.org/cheatsheets/Email_Validation_and_Verification_Cheat_Sheet.html#email-canonicalization)。

账户创建采用一个事务：锁定建档资格→核对绑定/期限→再次检查唯一性→插入 user/credential/验证依据→消费资格→建立受限会话→记录审计→提交。任何一步失败不留下半个账户；唯一索引必须兜底并发，而非只做“先查询”。

重复提交使用事务 ID 与请求幂等标识。若创建已成功但响应丢失，后续请求只能在同一浏览器绑定下返回“已完成，请登录”的安全结果；不创建第二账户、不重复消费、不把旧资格作为永久换取会话的凭据。已收到有效会话的浏览器可以继续到个人中心。

## 5. 验证码与注册资格

建议首期产品参数如下，均由服务端配置，不代表学校制度：

- 验证码：密码学安全随机生成的 6 位数字，10分钟有效，每个挑战最多5次错误尝试。
- 重发：60秒冷却，每个邮箱每小时最多5次、每日20次；另设按 IP/浏览器事务的限制，针对校园共享出口进行压测与调优。
- 重发替换同一注册事务的旧验证码；旧码失效。改变邮箱重新建立验证步骤，旧建档资格失效。
- 验证码保存为带服务端独立密钥的 HMAC，并绑定 purpose、邮箱、事务 ID、generation；不保存裸哈希或明文。建档资格使用至少256位安全随机值，只存摘要。
- 建档资格建议10分钟有效，绑定已验证邮箱、原浏览器事务与用途；只允许消费一次。不能接受“前端传来 verified=true”。
- 浏览器绑定采用生产环境 Secure、HttpOnly、合适 SameSite 的短期 cookie；所有写入操作核验受信 Origin 和 CSRF/事务绑定，CORS 不向任意源开放带凭据请求。
- 限流与尝试次数的更新即使接口返回验证码错误、过期或429也必须按规则提交，不能因外围事务 rollback 而丢失；用并发用例验证。
- 在邮箱控制权被证明前，对已有/不存在账户采用相同请求响应形态和合理一致的时序。证明后可提示“该邮箱已有账户，请登录或找回密码”，但不直接登录或自动合并。
- 注册、学校验证、改绑、恢复的凭据互不通用。测试捕获器只能用于隔离环境，真实模式没有读取验证码的调试接口。

没有可用的真实发件通道时，不能安全完成真实邮箱归属验证。可继续完成代码与隔离测试，但真实注册开放必须等待发件能力配置成功。

## 6. 接口契约

以下为建议接口，执行者可在保持语义的前提下按现有路由规范落地。响应不得携带哈希、验证码或内部部署细节。

| 接口 | 输入/前提 | 输出与行为 |
|---|---|---|
| `GET /api/v1/auth/capabilities` | 匿名 | 邮箱注册、密码登录、密码恢复、Google 的 enabled/available 状态；不返回凭据或内部地址 |
| `POST /api/v1/auth/email/registrations` | email、locale；同源/限流 | 建立短期注册事务，发送验证码；返回事务 ID、期限、可重发时间和发送状态，设置浏览器绑定 |
| `POST /api/v1/auth/email/registrations/{id}/resend` | 同一事务绑定、CSRF | 生成新 generation，旧码失效，返回后端时间 |
| `POST /api/v1/auth/email/registrations/{id}/verify` | code、事务绑定、CSRF | 原子消费验证码；成功后设置短期建档资格，后续无需前端持有可读的永久令牌 |
| `POST /api/v1/auth/email/registrations/{id}/complete` | username、password、事务/建档资格、CSRF、幂等标识 | 201 创建用户与凭据、设置登录邮箱验证时间、签发 onboarding 会话；返回现有 SessionDTO/nextAction |
| `POST /api/v1/auth/password/login` | 现有 identifier、password | 继续支持用户名或邮箱，补齐凭据验证条件、限流与错误时序防护 |
| `POST /api/v1/auth/password/forgot` | 登录邮箱 | 对存在/不存在账户返回相同安全提示；只给符合恢复条件的账户发送真实恢复凭据 |
| `POST /api/v1/auth/password/reset` | 恢复凭据、newPassword | 原子消费，更新密码、撤销旧会话；返回完成提示，不自动签发业务会话 |
| 个人中心登录邮箱补验接口 | 原凭据已认证的受限会话、CSRF、对应验证码 | 只补验该账户当前绑定的登录邮箱，更新验证事实并按规则轮换会话 |

已有 `POST /api/v1/auth/password/register` 必须同步关闭无验证建档路径：要么迁移为同一完成服务且强制有效建档资格，要么停止该旧语义并返回明确错误。仅改新表单、保留可绕过的新旧双入口不可验收。

验证与恢复响应设置 `Cache-Control: no-store`。请求关联 ID 全链路传递。错误码区分字段、过期、验证码错误、限流、连接故障与邮件暂不可用；对外文案不泄露内部栈或账户存在性。

## 7. 真实邮件发送与故障处理

### 7.1 最小可交付实现

沿用现有 SMTP 适配器并使其支持注册/学校验证/恢复三种用途和三语模板。首期可同步发送，无需仅为此引入新的队列产品；设定超时并在外部发送期间避免持有用户/凭据的长数据库事务。

建议顺序：持久化待发送挑战与限流事实→调用发件服务→更新 accepted/failed/unknown→响应。注册前没有永久账户，因此发件失败不会留下可登录的半成品用户。已失败或结果不确定的挑战按明确策略失效，界面要求重发最新验证码；迟到邮件中的旧码不能验证成功。

SMTP接受后响应丢失时，客户端显示状态不确定，允许在限流规则内重发，不显示注册成功。邮件服务器接受仅表示交付到发送系统，不保证进入收件箱。若后续改为持久任务队列，单独实现事务发件箱、加密的短期载荷、重试/去重/过期；不要把现有测试用明文 EmailOutbox 直接用于生产。

### 7.2 配置与运行隔离

- 生产核心配置：真实数据库、HTTPS站点、会话/挑战密钥；不得默认使用 dev 密钥。
- 邮箱注册配置：应用拥有的发件服务、允许使用的 From、认证凭据、明确的 TLS 模式；STARTTLS 与隐式 TLS 分别实现，并验证证书和主机名。接收邮箱不提供其个人邮箱密码。
- Google 关闭时不要求 Google client secret；邮件故障不阻断正常密码登录。Google 已启用但配置错误时，能力状态禁用该入口并记录运维错误，不把其他通道一起拖垮。
- 发件能力检查包括配置完整、网络/TLS/认证可用、发件身份允许；最终另做真实收信验收。readiness 不在每次探测时发测试邮件。
- 恢复请求在邮件整体不可用时，对任何邮箱返回一致的不可用反馈；若只某个账户/地址发送失败，不通过公开响应区别其是否存在。
- 不返回验证码给浏览器、不写控制台、不提供通用验证码。capture 只能用于隔离验证，不能宣称满足“我可以用自己的邮箱注册”。

## 8. 密码登录、重置与学校资格

### 8.1 密码存储与策略

新建或重置密码使用成熟实现的 Argon2id，建议从 `m=19MiB、t=2、p=1` 起按目标服务器压测调整；沿用既有 bcrypt 密码的验证能力，成功验证旧密码后可升级哈希，不强迫清空所有凭据。密码哈希方案依据 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

首期普通密码登录没有 MFA，建议新设密码15–128字符，允许长口令、空格、Unicode与粘贴，不强制复杂字符组合；拦截已知常见/泄露密码时使用本地检查或不泄露原密码的方式。前后端统一长度语义，禁止截断。历史较短密码仍能按原哈希验证，策略升级作用于新设/重置；当前 bcrypt 的72字节边界需保留正确验证，不把新策略直接套到旧登录上。参考 [OWASP 密码强度要求](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#implement-proper-password-strength-controls)。

登录失败采用统一提示；未知账户也执行适当的等价校验，减少明显时序差异。延续服务端多维限流，但避免以永久锁定方式让攻击者轻易使他人无法登录。

### 8.2 忘记密码

恢复仅针对已经存在且登录邮箱验证时间非空的密码凭据。纯 Google 账户不能通过“找回密码”偷偷新增本地密码，学校邮箱验证记录也不能在地址不同时替代登录邮箱恢复依据。

使用至少256位随机、限时（建议20分钟）、单次消费的恢复令牌，绑定用户、当前已验证登录邮箱、purpose和凭据版本，仅保存摘要。邮件链接回到受控 HTTPS 站点，不信任任意 Host 或 returnTo。

恢复页无第三方追踪，设置 no-store 与严格 Referrer-Policy；入口日志/监控对令牌脱敏。若使用 URL fragment，页面读取后尽快清除并仅在内存保留，最终通过 POST 提交；不要在 GET 请求中消费令牌，以免邮件安全扫描器触发重置。

提交时事务锁定并验证令牌，更新哈希与凭据版本、消费令牌、撤销现有会话和其他恢复凭据，记录审计。完成后通知已验证邮箱并返回登录页。请求找回本身不修改密码、不撤销现有会话、不解禁停用账户。原则参考 [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

### 8.3 学校邮箱与教师审核

复用既有学校邮箱验证流程。新登录邮箱验证码不能直接调用学校验证接口；两个 purpose 严格隔离。首期即使用户把学校邮箱用作登录邮箱，也保留个人中心里的学校验证步骤，避免仓促复用证据导致资格绕过；后续若减少重复验证，应单独定义同用户、同地址、证据时效和学校策略的复用规则。

教师申请只有当前资料与学校验证依据对应的有效审核才能授予权限。普通邮箱验证、密码重置、Google关联均不授予教师或管理员。学号匹配和实名核验按已确认学校规则执行，不能假设所有邮箱前缀就是学号。

## 9. 历史账户迁移与回滚

1. 先清点现有用户、密码凭据、邮箱比较规则与关联方式，备份并在隔离副本演练迁移；保留 ID、课程/项目关系和审核记录。
2. 先增加可空字段与注册事务表，再部署兼容旧 bcrypt 和新 Argon2id 的服务；前后端接口契约同步，最后切换新注册入口。迁移号不硬编码为0003，应接续执行时 head。
3. 旧 `login_email_verified_at` 保持空，除非已有可审计、严格对应同一用户和同一登录地址的验证证据。不得用“邮箱格式合法”“学校邮箱已验证但地址不同”“存在 Google 邮箱字段”批量补真。
4. 旧密码用户凭原密码进入受限补验流程；完成登录邮箱归属验证后，按学校资格重新计算可用范围。切换时撤销或降级不能证明来源与验证条件的旧密码会话。
5. 仅知道旧账户未验证邮箱的人，不能通过新注册或找回直接接管该账户。旧用户同时忘记密码且未验证登录邮箱时，走另一已绑定可信身份或受控人工恢复，不自动认领、合并或授予已有角色。
6. 纯 Google 用户保持原身份关联，不自动增加本地密码。后续设置密码必须在原账户近期认证后验证拟用登录邮箱；同邮箱也不自动合并两个已有账户。
7. 回滚优先关闭新注册入口、保留兼容读取与数据库新增字段；已产生 Argon2id 凭据后，不能回退到只支持 bcrypt 的旧程序。禁止把回滚实现为恢复无验证码的旧注册路径。
8. 注册前事务到期后按留存策略清理；建议过期24小时后移除邮箱与凭据材料，仅保留必要脱敏审计/限流记录。清理任务不得删除正式用户。

## 10. 实施拆分

| 批次 | 交付任务 | 与现有实现的关系 |
|---|---|---|
| E0 | 先按整改方案 R0 修复环境、配置加载、代理与迁移指向 | 先让真实服务链路可用；不先重写表单 |
| E1 | 迁移字段、预注册事务、挑战安全、邮件模板与提供方配置隔离 | 复用现有密码表/会话/限流；注册前挑战单独持久化 |
| E2 | 三步注册、完成接口、旧入口封堵、onboarding门禁 | 对现有登录页与客户端定点改造 |
| E3 | 密码找回/重置、旧账户补验、兼容密码哈希与会话撤销 | 密码用户对外开放前交付 |
| E4 | 隔离集成测试、真实邮件闭环、浏览器三语与窄屏验收 | 真实发件凭据与受控测试收件人由部署负责人提供 |

执行顺序遵循项目“需求→页面结构→已有设计与组件→实现→体验验证”；不为本次功能引入额外视觉库。更新数据库字典、接口交接表、路由映射、启动说明和阶段报告，使下一个 agent 能准确复现。

## 11. 验收用例

| 编号 | 场景 | 必须得到的结果 |
|---|---|---|
| E01 | Google 关闭且没有 Google 凭据 | 真实邮箱注册、密码登录、恢复仍能工作 |
| E02 | 输入普通邮箱请求注册 | 永久 users/密码凭据未创建；发件状态与真实结果相符 |
| E03 | 错误、过期、重复、重发前旧验证码 | 无建档资格；次数持久化；达到阈值拒绝 |
| E04 | 更换邮箱/浏览器/事务/用途重用验证码或建档资格 | 拒绝，不创建用户 |
| E05 | 两个并发请求消费同一建档资格 | 最多创建一个账户、一条有效凭据；无孤儿记录 |
| E06 | 两个事务注册同一邮箱或用户名 | 数据库唯一约束生效；失败事务完整回滚 |
| E07 | 直接调用旧 `/password/register` 或伪造 verified/role | 无验证资格不能建档或提权 |
| E08 | 邮件认证失败、超时、结果未知、邮件迟到 | 不显示已验证/注册成功；无永久用户；重发规则与旧码失效正确 |
| E09 | 数据库或鉴权后端不可达 | 稳定安全错误与关联编号；无 Mock回退或页面通行 |
| E10 | 建档成功但网络响应丢失，用户重试 | 不重复创建；可通过正常密码登录继续 |
| E11 | 账户创建成功但资料/学校验证未完成 | 仅个人中心可用；业务页、API及文件入口拒绝 |
| E12 | 学生完成全部条件，教师仍在待审核 | 学生按资源授权进入；教师仍受限，不能自行写角色绕过 |
| E13 | 已有账户与不存在账户的注册前/恢复请求 | 不通过公开码、响应结构或明显时序泄露存在性 |
| E14 | 恢复凭据过期/重复/邮箱变更/版本改变 | 拒绝；成功重置后旧密码、旧会话、其他恢复凭据失效 |
| E15 | 只请求找回而不提交有效凭据 | 原密码与当前有效会话保持可用 |
| E16 | 旧 bcrypt 账户登录、新 Argon2id 账户登录 | 均可正确验证；升级不丢账户或静默截断密码 |
| E17 | 未验证的旧登录邮箱被第三人用于新注册/找回 | 不接管旧账户、不自动合并、不取得其学校/角色资格 |
| E18 | 密码会话与 Google 会话并存、账户被停用 | 按各自认证依据与账户当前状态处理；不能借其他凭据绕过限制 |
| E19 | 多进程限流、错误码返回引发事务回滚 | 次数不丢失，不靠重启进程绕过；429倒计时一致 |
| E20 | 三语、360px窄屏、200%缩放、键盘、密码管理器 | 注册/登录/恢复可完成，无关键操作遮挡或不可达 |
| E21 | 真实普通邮箱与学校邮箱 | 脱敏记录发送接受及真实收件/验证码验证，捕获器不计作真实验收 |
| E22 | 验证后刷新、退出登录、服务重启 | 账户和验证事实持久化；已消费凭据不能重放 |

自动化使用隔离 PostgreSQL、测试邮箱捕获器和必要的本地测试提供方；真实验收使用受控测试账户，不发送无关邮件。执行者逐项写“通过/失败/未验证”，注明命令与环境。没有发件凭据时，E21必须记为未验证，不能用测试邮件正文替代。

## 12. 交给编程 agent 的范围指令

> 按本方案实施 E0–E4，优先修复当前注册请求的运行故障，再完成邮箱归属验证后建档的三步流程。邮箱登录必须独立于 Google，复用现有用户库和服务端权限门禁。同步关闭旧无验证注册路径，补齐密码恢复与历史密码账户补验，不通过未验证邮箱接管旧账户。保持资料、学校邮箱和教师审核在个人中心完成；仅 active 且具备资源权限者访问业务。修改前核查当前迁移、配置及未提交工作，禁止清库、重建项目或伪造验证码/投递成功。交付时提交真实根因、文件变更、迁移与回滚说明、E01–E22结果和剩余凭据依赖。真实邮件联调的缺失必须如实标记；代码完成与真实用户可注册分别验收。
