### How Translation Works (and Why Leaks Occur)

GroupProof uses two runtime localization mechanisms plus a third split hook:
1. **`next-intl` (`useTranslations` / `getTranslations`)** backed by `shared/i18n/messages/{zh-Hans,zh-Hant,en}.json` (**912** leaf keys; zero missing `useTranslations` keys found via TypeScript AST check).
2. **Global JSX runtime (`tsconfig.json` `jsxImportSource: "@/shared/i18n"`)** via `localizeProps()` (`shared/i18n/localize-props.ts`) and `tr()` (`shared/i18n/tr.ts`), backed by `shared/i18n/catalog/en.ts` (**4,265** keys) and `shared/i18n/catalog/zh-Hant.ts` (**3,995** keys). `localizeProps` translates `children` on all elements and `HOST_ATTRS` (`placeholder`, `title`, `aria-label`, `alt`, `label`, `aria-description`, `aria-roledescription`) **only** on intrinsic DOM elements (`typeof type === "string"`), and **only** when the rendered string matches a catalog key in full. It does **not** run on `window.confirm()`, `Error` messages, `Blob`/export generators, `input` `value` state, template interpolations (`...${x}...`), or `.ts` helper return values unless wrapped in `tr()`.
3. **`useUiText()` (`shared/i18n/use-ui-text.ts`)** reads `shared/i18n/catalog/en.json` (**600** keys) and `shared/i18n/catalog/zh-Hant.json` (**515** keys) instead of `en.ts`/`zh-Hant.ts`, and does not translate string placeholder arguments. Any `tr("...{0}...", ...)` call whose template key is missing from `en.json`/`zh-Hant.json` interpolates values into Simplified Chinese *before* JSX renders, breaking exact-key fallback in `localizeProps` and producing raw Chinese or mixed English+Chinese UI.
