# 学生端统一 UI 设计与实现规格

## 目标

将学生端 56 个入口统一到同一套工作台语言：开放画布、清晰的任务层级、紧凑的连续列表、按需展开的详情抽屉，以及一致的加载/空状态/错误/权限反馈。保留现有路由、权限、真实 API 和课程规则，不把视觉改版误作业务授权。

## 参考与取舍

参考 `oil-oil/oil-ui` 的 AI 友好设计方法和 `joeseesun/qiaomu-design` 的反模板化、可组合设计系统思路，但不复制其代码或品牌。落地到 GroupProof 时采用：

- 页面顶部只保留一个清晰的主动作和必要的上下文；
- 用时间线/连续行/分组列表承载活动和对象，避免每一段内容都包在厚重卡片里；
- 卡片只用于摘要、决策和需要强调的状态，不用于普通正文容器；
- 首屏优先显示“谁、做了什么、现在需要什么”，原始来源、完整 diff 和审计记录按需展开；
- 标签、图标、文字和状态点同时表达状态，不依赖颜色；
- 页面在 375px、768px、1440px 下保持可读，不产生页面级横向滚动。

## 视觉令牌

语义令牌集中在 `app/globals.css`，组件不得为同一语义再写新的颜色值。

| 语义 | 令牌 | 用途 |
| --- | --- | --- |
| canvas | `--gp-canvas` | 页面背景 |
| surface | `--gp-surface` | 工作区和浮层 |
| ink / muted | `--gp-ink`, `--gp-muted` | 主次文字 |
| action | `--gp-action`, `--gp-action-soft` | 主动作、链接、选中态 |
| success / warning / danger | `--gp-success`, `--gp-warning`, `--gp-danger` | 结果和风险 |
| line | `--gp-border`, `--gp-border-subtle` | 分隔和控件边界 |
| radius | `--gp-radius-control`, `--gp-radius-panel`, `--gp-radius-pill` | 控件、区域、标签 |
| rhythm | `--gp-space-1` … `--gp-space-8` | 间距节奏 |

字体层级固定为 page title、section title、body、meta、eyebrow 五级；正文行高不低于 1.5，交互控件的可点击区域不小于 36px。

## 页面模板

### 工作台首页

顺序为问候/当前上下文 → 四项关键统计 → 我的项目与课程 → 最近活动 → 快速入口。统计是轻量摘要，不嵌套进多层卡片；项目和活动使用列表行。

### 项目工作区

使用统一 `WorkspaceShell`：全局导航与当前项目导航分组显示。项目页顶部为面包屑、项目标题、生命周期状态和一个主动作。Plan、Collaborate、Review、Settings 使用可折叠分组，移动端改为抽屉。

### 列表/活动页

工具栏、筛选和连续列表是主结构。每行首屏显示头像/首字母、作者、时间、实现摘要和状态；原始链接、完整正文、diff、证据和历史放到右侧详情抽屉。列表行使用细分隔线而不是重复大边框。

### 表单/向导页

按任务分段，单个区块只保存一个关注点；保存状态靠近操作按钮，失败保留输入。两列布局只在宽屏启用，窄屏单列。

### 证据/文件/讨论页

使用“索引列表 + 详情抽屉”或“主列表 + 上下文栏”，避免把全文、来源和操作同时堆在首屏。

## 全局交互规则

- 主操作只出现一次；危险操作需要明确后果和恢复路径。
- 空状态给出一个直接下一步；不可用状态说明原因和重试路径。
- 列表支持键盘聚焦、Enter 打开详情、Escape 关闭抽屉；抽屉打开后焦点进入标题或关闭按钮。
- 所有 AI 结果显示“AI 生成 / 待人工确认”，不能直接改变正式数据。
- 外部同步失败不清空已有来源记录；原始来源和来源时间始终可追溯。
- 尊重 `prefers-reduced-motion`，动效只用于层级和反馈，不承载业务语义。

## GitHub AI 活动摘要

首期只对 `commit` 生成摘要；PR 和 CI 仍作为来源证据展示。简略行必须包含作者和实现内容，详情抽屉再展示影响范围、验证、风险、证据引用及原始提交链接。摘要按提交版本、提示词版本和输入哈希缓存；AI 失败不影响原始 GitHub 活动。

## 验收标准

1. 学生端主要页面共享同一套令牌、标题、按钮、状态、空态和抽屉组件。
2. 普通列表不再由连续的大边框卡片组成；只有摘要、决策和设置中心保留区域卡片。
3. GitHub 活动首屏能看到提交者和实现内容，详情按需打开。
4. AI 结果经过证据引用校验并标记人工确认，失败时保留原始活动。
5. 375px、768px、1440px 无页面级横向溢出，键盘可以完成主流程。
6. `lint`、`typecheck`、`build`、路由检查和针对性 API/浏览器测试通过。
