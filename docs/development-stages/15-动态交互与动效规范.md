## 业务规则与状态

B交付动效规范，组件/页面负责人实现。优先使用CSS和当前组件能力；进入/退出、状态变化和图表更新表现实际业务结果。业务保存/发布不依赖动画计时或结束事件。减少动效偏好下保留反馈且去除非必要位移；支持连续操作、取消和重新打开。

## 数据与操作接口

```text
运动基线：
常规状态变化 150–200ms，主要使用 ease-out；
按钮/弹窗/抽屉/Tab/列表变化共享规则；
数据图表更新随实际数据变化，不制造虚假进度；
提供正常和 prefers-reduced-motion 两套行为说明；
不因计划提到 ReactBits 而强制安装动效库。
```

## 实现步骤

1. 列出共享组件和代表页的状态变化：触发、开始状态、结束状态、可中断条件。
2. 定义时长/曲线/位移/透明度Tokens和减少动效替代，明确哪些状态需要即时反馈。
3. 给按钮、Dialog/抽屉、Tab、列表新增/更新与统计变化提供规范和参考。
4. 组件开发者先落地共享运动能力，各页面按统一规则接入。
5. 验证快速连续操作、关闭后重开、保存失败、权限变化和系统减少动效设置。
6. 有新库需求时先说明具体组件无法覆盖的能力、依赖影响与性能证据，再在任务范围内决定。

## 核心代码示例

```css
/* 规则参考；功能操作由真实状态驱动 */
.gp-transition {
  transition: opacity 180ms ease-out, transform 180ms ease-out;
}
@media (prefers-reduced-motion: reduce) {
  .gp-transition {
    transition: none;
    transform: none;
  }
}
```

示例应在上述接口与现有代码中接入；接口定义片段不应被当作已经实现的服务。

## 页面接入与错误反馈

动效与当前任务状态、焦点和输入一致；减少动效下依旧显示保存结果、错误和加载状态。动画不隐藏错误信息或让键盘焦点移出可见范围，不阻塞用户完成主要操作。

## 测试场景

- 快速点击、切换、关闭重开不会产生状态错乱或重复提交。
- 减少动效时功能和重要反馈完整。
- 焦点、滚动与弹窗行为稳定，核心操作与业务测试继续通过。
- 动效不会产生明显布局抖动或给弱设备带来无理由的额外成本。
