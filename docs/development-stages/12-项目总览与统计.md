## 业务规则与状态

总进度按顶层任务权重计算，核心进度按核心模块中的顶层任务计算；子任务先汇总到父任务，不重复计算。分母为0时显示暂无计划，不显示虚构完成度。正式当前计划用于执行统计，草稿统计明确标为预览。公开总览只含五个允许字段，不能传整个core对象再隐藏元素。

## 数据与操作接口

```ts
interface ProgressSummary {
  overall: number | null;
  core: number | null;
}
// getProjectSummary(projectId): Promise<ProjectSummary>
// getProjectOverview(projectId): Promise<ProjectOverviewModel>
// 私有OverviewModel含当前版本、进度、本人任务、里程碑、待处理及动态。
function weightedProgress(tasks: Task[]): number | null {
  const total = tasks.reduce((sum, item) => sum + item.weight, 0);
  if (total <= 0) return null;
  return Math.round(
    tasks.reduce((sum, item) => sum + item.weight * item.progress, 0) / total
  );
}
```

## 实现步骤

1. 写独立选择器，从 activePlan/currentTask 集合派生进度；父任务进度与任务执行负责人统一口径。
2. 核心统计只筛选 module.core 的根任务，用其权重重新归一。
3. 总览接口分公开DTO和私有ViewModel，读取时分别执行summary/content规则。
4. 当前里程碑和阶段日期来自同一milestone集合，初始化/基线/计划状态显示各自的实际版本。
5. 待处理与动态引用真实ActionItem、任务、证据或日志，避免按固定列表模拟已发生的事件。
6. 工作区提交后选择器和相关缓存统一更新，刷新结果一致；只读教学人员不显示本人学生操作。

## 页面接入与错误反馈

沿用总览面板，区分未初始化、待确认、已发布计划、复核中、已定稿和已归档。公开读者渲染独立组件；空计划和无里程碑有具体说明；相关入口根据权限和实际状态展示。

## 测试场景

- 父子任务不重复计权，根任务更新后总览/树/看板/列表一致。
- 无任务或权重分母0显示暂无计划。
- 核心模块筛选正确，普通模块变化不误改核心进度。
- 同课其他组只能得到五个公开字段，私有接口拒绝。
- 切换当前正式版本、归档或规则复核后各状态与入口正确。
