## 业务规则与状态

本阶段文件操作沿用 Mock：明确标记模拟上传/预览/下载，不声称浏览器元数据等于真实文件保存。读取按项目 content.read；上传/替换按 files.write 并要求 active 项目。统一支持原有格式且每个文件≤50MB。一个项目内同名文件关联逻辑文件，替换生成新 FileRecord 版本，旧版本保留。用于正式基线的 sourceFileId 引用不能被静默替换或删除。

## 实现步骤

1. 实现唯一的格式/字节大小校验器，解析当前两个入口支持格式并统一使用。
2. 元数据保存原始 sizeBytes 和 MIME，不以展示字符串作为大小校验依据，兼容旧size文本。
3. 新增逻辑文件/版本关联，替换时原子新增版本、标记旧current为superseded，当前指针唯一。
4. 把初始化上传和资料中心接入同一 FileService 与记录集合，保留项目与课程来源。
5. 按逻辑文件和版本实现检索、排序、筛选、历史查看；完整读取校验所属项目。
6. 当前预览/下载返回明确演示内容；为未来真实上传、完成确认、预览、下载设计相同的权限与文件版本契约。
7. 对正式来源引用保留历史 ID，替换后提示是否需要基线变更，不直接改正式snapshot。

## 核心代码示例

```ts
function validateUploadSize(sizeBytes: number): void {
  if (!Number.isSafeInteger(sizeBytes) || sizeBytes < 0 ||
      sizeBytes > 50 * 1024 * 1024) {
    throw new Error("单文件大小必须在 0–50MB 范围内");
  }
}
// 替换前核对 replacesFileId.projectId 与输入 projectId 一致，
// 使用原始 byte 数及允许的格式白名单，统一更新历史和当前版本。
```

示例应在上述接口与现有代码中接入；接口定义片段不应被当作已经实现的服务。

## 页面接入与错误反馈

沿用现有资料页与上传入口。上传中、单文件失败、重试、无权限、空结果、历史版本清晰反馈；不能全选多文件后一概显示全部上传成功。归档项目展示只读。模拟环境标记帮助用户判断文件是否真的存储。

## 测试场景

- 50MB边界一致，超限或不支持格式不改变已有current版本。
- 同名替换增加版本，旧版本可查，正式snapshot仍引用原fileId。
- 跨项目fileId/替换对象拒绝，课程公开总览用户不能下载项目资料。
- 部分文件失败逐个反馈，重复提交不重复创建同一次结果。
- 刷新后元数据和版本恢复，页面明确反映Mock范围。
