## 业务规则与状态

紧凑、克制、清晰数据比较，服务学生/组长与教师管理。全局规范覆盖全部56页，但B不因此承担其他成员的全部页面编码。保留数据/接口语义及URL，统一Tokens和组件状态后推广。采用系统中文无衬线字体，正文默认14px，避免新增外部字体加载依赖。

## 实现步骤

1. 回顾已稳定的用户流程与信息架构，制作必要线框；处理已记录的密度、层级和布局问题。
2. 定义颜色、字体、间距、尺寸、圆角、层级、响应式与状态Token命名，写清现有CSS变量的映射和迁移。
3. 定义按钮/表单/表格/筛选/状态/步骤条/弹窗/空错误状态的接口、变体与全部状态表现。
4. 完成四类模板及三张代表页参考稿，覆盖窄屏、长文本、只读、版本差异与错误反馈。
5. 把56页映射到模板，交给各前端负责人先实现共享组件和代表页，再推广至其业务页面。
6. 验收规范与参考的一致性；各编码负责人完成页面视觉和行为回归，更新其记录。

## 页面接入与错误反馈

基于真实表单、字段和状态设计，不改变功能规则。普通正文对比度≥4.5:1，可见键盘焦点、明确标签与字段错误；响应式代表宽度375/768/1024/1440px。密集表格允许局部滚动，页面主体保持可用；手机主要操作触达尺寸按44px设计。

## 测试场景

- Tokens与组件表覆盖正常/hover/focus/disabled/loading/error/success。
- 三张参考稿覆盖版本/权限/空错误状态，不仅绘制成功页面。
- 代表宽度、长文本、表格和弹窗布局可用，键盘焦点清晰。
- 其他页面开发者能用规范匹配模板并保留业务契约。
