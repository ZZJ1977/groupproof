## 业务规则与状态

## 实现步骤

1. 定义命令输入和 DomainError；用 Zod 对每个命令做严格字段校验。
2. 新增执行队列：读取最新状态和当前会话 → 输入/权限/版本/状态校验 → 不可变地生成新状态及日志 → 保存 → 更新 React Query。
3. 用归档命令做第一条完整链路；注入 actorId/now/logId，不允许 UI 指定他人身份。
4. 为其他领域注册命名命令；未实现的操作明确返回错误，不伪造保存成功。
5. 建立通用 CRUD 调用清单，B 受控字段迁移到命令；其他模块涉及成员、进度、定稿的操作同步接入其受控命令。迁移未结束前不声称全项目已统一写入口。
6. 公开 Hook 返回有类型的操作和 pending/error；内部存储原语不作为页面任意修改受控对象的接口。
7. 定义未来 HTTP 适配边界：服务端会话确定身份，数据库事务和条件版本更新执行同等规则。

## 核心代码示例

```ts
import type { MockData } from "@/types/domain";
import { can } from "../access/policy";

export type ErrorCode =
  "NOT_FOUND" | "FORBIDDEN" | "VERSION_CONFLICT" | "INVALID_STATE";

export class DomainError extends Error {
  readonly code: ErrorCode;
  constructor(code: ErrorCode, message: string) {
    super(message);
    this.name = "DomainError";
    this.code = code;
  }
}

export function applyArchive(
  data: MockData,
  context: { actorId: string; now: string; logId: string },
  input: { projectId: string; expectedVersion: number }
): MockData {
  const project = data.projects.find(item => item.id === input.projectId);
  if (!project) throw new DomainError("NOT_FOUND", "项目不存在");
  if (!can(data, context.actorId, "project.archive",
    { kind: "project", id: project.id }))
    throw new DomainError("FORBIDDEN", "当前用户不能归档此项目");
  if (project.version !== input.expectedVersion)
    throw new DomainError("VERSION_CONFLICT", "项目已更新，请刷新后重试");
  if (project.lifecycle !== "finalized")
    throw new DomainError("INVALID_STATE", "项目必须先定稿才能归档");

  return {
    ...data,
    projects: data.projects.map(item => item.id === project.id
      ? { ...item, lifecycle: "archived", version: item.version + 1 }
      : item),
    logs: [...data.logs, {
      id: context.logId, actorId: context.actorId,
      action: "归档项目", target: project.id,
      result: "success", ip: "mock", createdAt: context.now,
      detail: "归档版本 v" + project.version
    }]
  };
}
```

该归档样例已做内存类型/规则验证，目标文件位置为 lib/commands/project.ts。完整执行器还需实现保存、缓存和 UI 接入。

示例应在上述接口与现有代码中接入；接口定义片段不应被当作已经实现的服务。

## 页面接入与错误反馈

使用原有按钮样式，资格控制入口；业务状态控制 disabled 及说明。操作期间禁用重复提交；版本冲突保留输入并提示重新核对；存储失败提示重试。加载、保存和错误反馈属于功能交付。

## 测试场景

- 普通成员直接调用归档命令仍被拒绝。
- 进行中项目不能归档，只有 finalized 可以归档，版本正确时更新为 archived。
- expectedVersion 过期拒绝，原对象和日志均不被修改。
- 保存失败不更新缓存；连续写按最新版本处理。
- 日志、主体与关联数据同批提交；授予/撤销助教权限后的下一次操作读取最新授权。
