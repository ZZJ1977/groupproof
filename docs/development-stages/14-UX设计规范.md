## 1. 信息架构与交互（先于视觉）

### 1.1 导航（按用户任务分组）

| 分组 | 项目（成员/组长） | 教师/助教 | 个人 |
|---|---|---|---|
| 入口 | 项目总览、项目初始化、需求基线、任务规划 | 课程总览、小组 | 首页、我的课程 |
| 执行 | **任务（树/看板/列表单入口，页内切换）**、里程碑、证据中心 | 待处理、报告 | 待处理事项、通知、个人动态 |
| 协作与产出 | GitHub、协作记录、文件资料、讨论区、贡献、报告 | 课程设置 | — |
| 配置 | 项目设置 | — | — |

- 导航链接与横幅名称**跟随当前对象**（项目名/课程名来自数据），不使用固定示例 ID。旧任务链接 `?view=tree|board|list` 保持有效。
- 教学人员进入项目页为只读视图，不显示学生操作入口。

### 1.2 页面级信息层级

- **总览**：当前阶段/状态 → 本人待办 → 阻塞原因 → 直接处理入口 → 统计与明细。统计区分“已定稿 / 待定稿 / 进度”，不把 100% 进度表述为完成或验收。
- **规划页**：正式版与草稿分区；集中展示结构问题（校验列表）、责任确认（逐人 + 时间）、发布条件（缺什么）。
- **规则配置**：修改差异（前→后）→ 影响对象（项目/小组/材料/里程碑）→ 复核要求与调整入口。
- **列表/详情**：筛选与视图切换在顶部固定；详情右栏放关联与操作。
- **分步表单**：步骤条 + 每步保存状态 + 前后移动不丢数据。

### 1.3 角色与权限表达

- 无资格：隐藏入口或显示权限说明（含原因与替代入口）。
- 有资格但前置未满足：禁用 + 就近解释（如“需全员确认后发布”）。
- 正常发布与例外推进**分开**为两个操作；例外推进必填原因并展示未确认名单后果。

### 1.4 表单保存状态机（全站统一）

`未保存 → 保存中（按钮 loading+禁用）→ 已保存（成功提示，含对象/版本）→ 失败（保留输入、错误关联字段、可重试）`
版本冲突提示“请刷新核对后重试”；重复提交由禁用与命令幂等双重防护。

## 4. 四类模板

1. **总览**：状态条 → 关键指标（口径明确）→ 我的待办/阻塞 → 直接入口 → 明细面板（版本/计划/统计）。
2. **列表详情**：页头+筛选工具条 → 表格/卡片列表 → 右侧详情与关联 → 行内操作。
3. **分步表单**：步骤条 → 步内容（字段组+帮助）→ 保存状态与导航（上一步/保存并继续）。
4. **规则与版本比较**：版本头（来源→目标、发布者/时间）→ 差异表（字段 前→后）→ 影响分类+调整入口 → 确认操作（正常/例外分离）。

## 6. 状态与交互说明（三代表页共用规则）

- 正常：主操作右上或行尾固定；次操作描边；危险操作红色描边+确认。
- 加载/保存中：按钮文案+禁用；页面级用轻量提示，不遮内容。
- 空数据：说明 + 主入口（如“创建变更草稿”）。
- 错误：字段级（fieldErrors）+ 表单级（message）；保留输入；重试按钮。
- 只读（教学人员/无资格）：隐藏写入口，展示权限说明。
- 禁用：旁注原因（如“需全员确认”“仅组长”）。
- 版本变化：VERSION_CONFLICT → “项目/课程已更新，请刷新核对后重试”，保留输入。
