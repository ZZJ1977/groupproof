## 目标与前置依赖

## 业务规则与状态

创建资格依据目标小组的成员/组长关系，而非全局 leader 标签。新建课程项目使用 active 课程、有效组员范围和已发布规则。课程强制约束始终适用；course/blank 只控制可选模板初始化。已有当前项目时返回现有项目入口，不产生第二个同组项目。项目与里程碑、组关联、日志同批提交。

## 实现步骤

1. 从 groupId 解析真实小组和课程，执行 project.create 的 group 目标权限；不信任表单传来的组长/成员名单。
2. 校验课程状态、最新规则指针、组人数、输入及 expectedGroupVersion；发现有效已有项目时给出现有入口。
3. 分配稳定 ID，创建 not_initialized/active 的项目，保存成员名单和 appliedCourseRuleRevisionId。
4. 按选定模板模式从指定规则快照生成里程碑，每个里程碑归属新项目，不引用旧项目的实际里程碑。
5. 同批更新 Group.projectId 与版本、写创建日志；失败时不留下孤立项目或里程碑。
6. 提交成功返回 project.id 并跳转现有 setup URL；让后续基线服务读取相同项目 ID。

## 核心代码示例

```ts
const target = { kind: "group", id: input.groupId } as const;
if (!can(data, context.actorId, "project.create", target)) {
  throw new DomainError("FORBIDDEN", "只有该小组组长可以创建项目");
}
const group = data.groups.find(item => item.id === input.groupId)!;
const existing = data.projects.find(item => item.id === group.projectId);
if (existing) return { project: existing, alreadyExists: true };
// 后续校验并构造新 project/milestones/group/logs，由执行器一次保存。
```

示例应在上述接口与现有代码中接入；接口定义片段不应被当作已经实现的服务。

## 页面接入与错误反馈

沿用创建步骤与样式。说明采用的课程规则版本；未加入小组或不是该组组长时给出合理入口/权限说明。重复点击期间禁用按钮，已创建时展示并进入现有项目。类型和截止日来源于课程，不允许界面绕过约束。

## 测试场景

- 全局 student 但为该组组长可以创建；其他组长不能跨组创建。
- 没有已发布规则、课程已结束、人数不满足条件时明确拒绝。
- 重复创建返回同一现有项目，集合无额外副本。
- 版本变化提示重新确认规则；创建失败不改变 Group.projectId。
- 选模板后新里程碑拥有正确 projectId，旧课程/项目数据不被改写。
