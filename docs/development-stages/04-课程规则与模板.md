## 业务规则与状态

所属教师管理课程，助教按独立 action 授权编辑/发布；授权管理仅属于课程教师。课程业务规则在 ended 后保持只读，授权撤销仍可处理。规则草稿不覆盖已发布版本。修改原因必填；组队最小人数≥1、最大人数≥最小人数，组队截止不晚于项目截止；阶段标题/日期与必交材料完整。评分仅管理说明，不实现贡献或评分算法。

## 实现步骤

1. 将教师编辑表单映射到结构化 payload，初始化时保留旧规则文本并显式呈现遗留条款。
2. 通过命令保存草稿；预览与读者展示使用同一结构化数据。
3. 发布时校验资格、内容、原因和版本，创建历史快照并更新 Course 的当前发布指针及兼容字段。
4. 给每个关联小组生成包含 ruleRevisionId 的复核待处理项，重复发布请求不重复生成提醒；仅发布后通知。
5. 在现有教师课程设置中提供助教关联与三个操作授权控制；授权输入白名单不含 staff.manage，日志记录授予和撤销。
6. 课程总览读取最新已发布模板；旧项目仍保留其 appliedCourseRuleRevisionId。
7. 同规则变更阶段约定版本查询/影响接口，本阶段只发布变更，不直接改写项目基线。

const editableCourseActions: DelegatedPermission[] = [
  "course.settings.update", "course.rules.edit", "course.rules.publish"
];
function validateGrant(permissions: string[]): void {
  if (permissions.some(item =>
    !editableCourseActions.includes(item as DelegatedPermission)
  )) {
    throw new Error("包含不允许授予助教的权限");
  }
}

## 页面接入与错误反馈

继续现有教师页样式。编辑和发布分别判断 action；无发布权限的助教可保存其获准草稿。发布前显示版本和影响项目数；表单字段错误就近显示；保存失败保留输入。课程成员阅读已发布规则，草稿仅供获准编辑者读取。

## 测试场景

- edit-only 助教能保存但不能发布；其他课程助教/教师不能修改。
- 无原因、无效人数、颠倒日期和不完整模板拒绝发布。
- 未发布草稿不出现在学生课程规则总览。
- 发布 v2 保留 v1、创建真实提醒且不会修改已有项目基线。
- 撤销授权后后续编辑拒绝；助教不能自授发布或授权管理权限。
