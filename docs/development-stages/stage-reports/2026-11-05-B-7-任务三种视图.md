### 接口

`GET /api/v1/projects/{id}/tasks?view=tree|board|list&q=&status=&assignee=&module=&milestone=&sort=&page=&page_size=`

- 返回任务行、总数、计划的 `lock_version` 和状态、每列数量、可选的模块/成员/里程碑。
- `q` 搜索名称、说明和编号（`T-001`、`t1` 都可以）；`assignee` 可以是成员 ID、`me` 或 `none`；`sort` 可选 `code`、`title`、`priority`、`weight`、`progress`、`status`、`updated`，前面加 `-` 表示倒序。
- 参数不合法返回 `422 INVALID_FILTER`。
- 树视图不分页，并把命中任务的上级一起返回（`matched=false`，页面淡色显示），另外返回 `integrity_issues`；看板不分页；列表分页。

### 需要说明的设计决定

1. **坏数据只诊断不修**：树视图复用 B-6 的校验规则，挑出父子成环、父任务不在本项目（孤儿任务）、前置任务不在本项目、模块或需求属于别的项目这几类，列在页面顶部，对应的行标“数据有问题”。成环的任务找不到根，就放在顶层显示，页面不会因此出错。
2. **B 不改状态**：每张卡片的 `transitions` 按 C 的规则算好。能开始的卡片可以拖到“进行中”，确认后由页面直接调 C 的 `POST /api/v1/tasks/{id}/start`；“进行中”到“待提交”只会打开 C 的提交页。C 拒绝时卡片留在原列，页面写明原因（例如“前置任务还没完成”）。不能动的卡片 `draggable=false`，鼠标悬停和卡片上都会显示原因。每张能动的卡片还有“移到…”按钮，不用拖也能操作。
3. **三个视图共用缓存**：查询键都以 `["b-tasks", 用户, 项目]` 开头，任何一次改状态成功后一起失效，所以切到列表或树时马上看到新状态。
4. **筛选写在链接里**：搜索、状态、负责人、模块、里程碑、排序、页码、树的收起状态（`collapsed`）都在 URL 上，复制给别人打开看到的是同样的视图。
