### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/projects/{id}/requirements?code=&q=&source=&module=&status=&page=&page_size=` | 分页查询；`source` 可为 `ai`、`manual` 或资料 ID |
| GET | `/api/v1/projects/{id}/requirements/{rid}` | 需求详情、当前版本、是否必须写原因 |
| PATCH | `/api/v1/projects/{id}/requirements/{rid}` | 修改需求；冻结后必须带 `reason`，否则 409 `BASELINE_FROZEN` |
| POST | `/api/v1/projects/{id}/requirements/{rid}/impact-preview` | 保存前列出受影响的任务和验收标准（只读） |
| GET | `/api/v1/projects/{id}/requirements/{rid}/versions[?from=&to=]` | 版本列表；带 from/to 时返回字段级差异 |
| GET | `/api/v1/projects/{id}/requirements/{rid}/trace` | 需求→模块→任务→验收标准→证据→验收结果 |
| GET | `/api/v1/projects/{id}/criteria-rechecks?task_id=` | 需要重新检查的验收标准（给 C 的任务页用） |

### 需要说明的设计决定

1. **冻结后能不能改需求**：B-4 要求冻结后编辑接口返回 `BASELINE_FROZEN`，B-5 要求冻结后写了原因可以改。两条一起满足的做法是：冻结后不带原因修改返回 `BASELINE_FROZEN`（并在 `details` 里说明需要原因），带原因则保存为新版本。模块、资料、范围等初始化内容冻结后仍然不能改。冻结的基线快照不变，之后的修改只体现在需求版本里。
2. **内容没变的保存不产生新版本**；草稿期的保存也留版本。
3. **需要重新检查**：保存后，关联任务（`task_requirements`）的所有验收标准都标记“需要重新检查”，并按任务调用 `VerificationPort.invalidate_criterion_results` 通知 D。D 未接入时标记照样保存，记为“未通知 D”，等 D 接入后可以补发。
4. **编号**：用数据库原子计数器分配，同时创建也不会重号；AI 重新分析删掉的需求，编号不会再给别的需求用。
5. **证据链各层的链接**：模块→页面 09 按模块筛选；任务→任务详情（页面 14）；证据→证据中心（页面 20，带证据 ID）；验收结果→验收页（页面 17）。D 未接入时验收结果显示“暂不可用（验收服务未接入）”。
