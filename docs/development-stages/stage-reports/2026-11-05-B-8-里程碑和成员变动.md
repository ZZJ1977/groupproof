### 接口

- `GET /api/v1/projects/{id}/milestones`、`GET .../milestones/{mid}`
  - 返回进度、关联任务、交付物和勾选记录、改期记录、本项目文件，以及当前用户能否操作（`can_lead`）。
  - `risk` 返回 `null`。
- `POST .../milestones/{mid}/deliverables`：添加交付物，只有组长能用。
- `POST .../deliverables/{did}/check`：勾选或取消勾选，`{done, file_id?, expected_version}`。
- `POST .../milestones/{mid}/complete`：确认阶段交付，`{expected_version}`。
- `POST .../milestones/{mid}/reschedule`：改期，`{deadline, reason, expected_version}`。
- `GET /api/v1/groups/{gid}/members/{uid}/open-tasks`：列出这位成员的未完成任务、可选的接手人，以及提交后是否立即生效。
- `GET / POST /api/v1/groups/{gid}/membership-changes`：查看本组的申请，或发起移出、退出，`{change_type, member_id?, reason, handovers:[{task_id, to_user_id}]}`。
- `PUT /api/v1/membership-changes/{rid}`：老师要求补充后，申请人修改并重新提交。
- `GET /api/v1/courses/{cid}/membership-changes?status=`：老师和助教查看本课程的申请。
- `POST /api/v1/membership-changes/{rid}/decide`：老师处理，`{decision: approve|reject|needs_info, comment?, expected_version}`。驳回和要求补充都必须写意见。

### 需要说明的设计决定

1. **进度不存表**：每次读取时用 C 的汇总函数计算。所以任务一变，里程碑进度马上跟着变，和任务页面的口径一样。如果一个子任务和它的父任务都关联了同一个里程碑，子任务只算一次。
2. **交付物关联的文件不加外键**：一开始给 `file_id` 加了指向 C 文件表的外键，结果 C 自己的迁移降级测试失败了。现在 `file_id` 只存 ID，B 在写入时检查这个文件属于本项目。
3. **完成后锁定**：阶段交付确认后，交付物、改期都返回 `MILESTONE_COMPLETED`。
4. **成员变动“全部成功或全部不变”**：
   - 生效时先锁项目，再锁小组。
   - 然后重新检查三件事：人是否还在组里、交接是否覆盖了所有未完成任务、接手人是否还在组里。
   - 检查通过后，结束小组和项目的成员关系，转移任务负责人，记下交接时间，关闭老师待办，再发通知。
   - 任何一步出错，整个事务回滚。测试里故意让接手人先离组，再让老师批准：结果返回 `HANDOVER_TARGET_LEFT`，成员、任务负责人、申请状态和老师待办都没有变。
5. **何时直接生效**：组队截止前（并且课程进行中、名单没冻结）提交会立即生效；截止后只给老师生成待办，在老师批准前人还在组里。
6. **老师待办带版本号**：待办的来源是 `b:membership-change:{id}:v{版本}`。老师要求补充后，申请人重新提交会生成一条新的待办，旧的那条已经关闭。
7. **组长不能直接退出**：会提示先更换组长（`LEADER_MUST_TRANSFER`）。组长也不能移出自己。
