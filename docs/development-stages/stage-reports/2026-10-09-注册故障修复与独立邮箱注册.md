# 迭代总结：注册故障修复（R0）与独立邮箱注册/恢复（R1）

日期：2026-10-09 · 依据：[交付缺口与故障整改方案](../../plans/2026-10-08-auth-delivery-risk-remediation.md)（R0/R1）、[独立邮箱注册方案](../../plans/2026-10-08-independent-email-registration-plan.md)（E0–E4）· 状态：R0/R1 完成并验证；R2/R3 分批推进中（见剩余限制）

## 一、注册失败根因（已确认，附证据）

| 层 | 证据 | 结论 |
|---|---|---|
| 服务未监听 | 执行时 `127.0.0.1:3000/8000/55432` 均 connection refused；Docker 守护进程未运行 | “当前无法注册”的直接原因之一；前端把网络失败与服务端 503 显示为同一“服务暂不可用” |
| 配置/数据库指向 | 无 `.env` 启动 uvicorn（复现命令 `npm run server:dev` 等价）→ 注册 503 `SERVICE_UNAVAILABLE`（requestId 489a6a2849c14e2b）；后端日志 `password authentication failed for user "gp"`；同一请求改用正确 `DATABASE_URL` 即 200 | **主因：`config.py` 的 DATABASE_URL 默认值 `gp:gp@…/gp_dev` 与实际开发库凭据不一致，且 README 的 `DATABASE_URL=… alembic upgrade head` 只作用于迁移单条命令，uvicorn 未沿用** |
| 错误可定位性 | 旧全局兜底仅返回 503+requestId，未按层级分类记录；`/healthz` 不查库 | 故障不可定位、healthz 成功≠可注册 |
| 运行缓存冲突 | `npm run build` 与 `npm run dev` 共用 `.next` 后业务页 500：`Cannot find module './vendor-chunks/lucide-react.js'` | 开发/构建输出目录混用导致不可重复启动 |
| 配置脆弱点 | 空环境变量 `DATABASE_URL=` 会覆盖默认值为空串；`.env` 路径随启动目录漂移 | 配置加载不可重复 |
| 迁移状态 | 运行库 `gp_dev` alembic 版本 0002/0003、`users`/`password_credentials` 均在 | 迁移遗漏不是本次故障原因 |

> 说明：密码注册接口本身不调用 Google/SMTP；QQ 邮箱、Google、SMTP 均非本次故障原因（方案 §2 的判定得到复核确认）。

## 二、R0 修复内容

- **配置加载**（`server/app/config.py`）：`.env` 固定为仓库根目录稳定路径（`GROUPPROOF_ENV_FILE` 可覆盖），环境变量优先，空值不覆盖默认；新增提供方开关 `AUTH_GOOGLE_ENABLED/AUTH_PASSWORD_ENABLED/AUTH_EMAIL_SIGNUP_ENABLED/AUTH_PASSWORD_RESET_ENABLED`；real 模式只强校验核心依赖（数据库/HTTPS/核心密钥），可选提供方“启用但未配置”才拒绝启动（发布检查），不再“真实模式=所有提供方必须可用”。
- **统一启动**：`server/scripts/start-dev.sh`（`npm run server:dev`）＝加载配置→打印脱敏配置来源与数据库标识→数据库可达性/迁移版本检查→幂等 `alembic upgrade head`→启动；`npm run server:readiness` 查 `/readyz`。
- **可观测性**（`main.py`/`errors.py`）：`/healthz`（liveness）与 `/readyz`（数据库/迁移/核心密钥，失败 503+可定位日志）分离；`GET /api/v1/auth/capabilities` 返回各入口 enabled/available（不含密钥/内部地址）；错误分类：存储类 503 `SERVICE_UNAVAILABLE`、未预期 500 `INTERNAL_ERROR`，均带 requestId 与脱敏分类日志；429 带 `Retry-After` 与响应体 `retryAfterSeconds`。
- **前端错误体验**：`ApiError` 保留 status/code/requestId/retryAfter/fieldErrors；网络不可达独立 `NETWORK_ERROR` 文案（“暂时无法连接注册服务”）；非 JSON 代理错误安全提示；失败提示附可复制请求编号与倒计时。
- **可重复启动**：`next.config.mjs` 增加 `distDir`（开发 `.next-dev` / 构建 `.next` 分离），消除 vendor-chunks 冲突，无需清理缓存。

## 三、R1 独立邮箱注册闭环（E0–E2）

- **数据**（迁移 `0003_pre_registration_and_login_email.py`）：新增 `pre_registration_requests`（事务 ID、邮箱/比较值、浏览器事务摘要、验证码 HMAC、generation、期限、错误次数、发送状态、消费时间、建档资格摘要/期限、完成时间、结果 user_id）；`password_credentials` 增 `login_email_verified_at/verification_evidence_ref/credential_version`（历史行保持空=未验证，不批量补真）；`sessions` 增 `auth_method/credential_version`；`email_challenges` 增 `credential_version`。字段字典同步更新。
- **三步注册**（`services/pre_registration.py` + `routers/auth.py`）：`POST /auth/email/registrations`（建事务+真实发码，发件失败明确报 `MAIL_UNAVAILABLE` 且事务保留可重发）→ `{id}/resend`（新 generation，旧码失效，冷却/限流）→ `{id}/verify`（行锁一次性消费验证码，签发限时一次性建档资格，≥256 位随机仅存摘要）→ `{id}/complete`（锁行→核对资格/期限→唯一性→单事务插入 user+credential+`login_email_verified_at`→消费资格→签发 onboarding 会话→审计；并发由唯一约束兜底，失败整体回滚）。验证前不创建永久账户、不占用用户名、对已有/不存在账户同形态响应；验证码/资格绑定浏览器事务 Cookie（HttpOnly）；修改邮箱即重开事务、旧资格作废。
- **旧路径封堵**：`POST /auth/password/register` 返回 410 `REGISTRATION_CLOSED`（E07，无绕过入口）。
- **邮箱与学校邮箱分离**：登录邮箱允许 QQ 等普通邮箱；学校邮箱仍在个人中心按域名规则验证，两个 purpose 严格隔离。
- **密码**：新设/重置用 Argon2id（m=19MiB,t=2,p=1），历史 bcrypt 兼容验证并在成功登录后升级哈希（E16）；策略 15–128 字符、允许长口令/空格/粘贴、本地常见弱口令拦截。
- **门禁复用**：建档后仅 onboarding 会话（资料→学校邮箱验证→教师审核→active+资源权限），直链/API/文件入口同样受限（E11）。

## 四、R1 密码恢复与历史账户（E3）

- `POST /auth/password/forgot`：存在/不存在账户统一安全反馈（E13）；仅“登录邮箱已验证”的密码凭据发放恢复凭据（256 位随机、20 分钟、单次消费、绑定凭据版本，只存摘要，邮件链接以 URL fragment 携带并在页面内即刻清除）。
- `POST /auth/password/reset`：事务内锁行校验→更新 Argon2id 哈希→凭据版本+1→消费令牌→撤销全部会话与其他恢复凭据→审计→通知（尽力而为）；不自动签发业务会话；重放/过期/版本变化拒绝（E14）；只请求找回不动密码/会话（E15）。
- **历史账户**：`login_email_verified_at` 为空的密码凭据——会话 scope 上限 onboarding（不得借 active 状态取得 full），nextAction=`verify_login_email`；`/account/security` 提供受限补验（真实验证码）；未验证登录邮箱不能用于找回，也不能被第三人经新注册/找回接管（E17，唯一约束兜底）。
- Google 会话不受另一条未验证密码凭据影响；同邮箱不自动合并；Google/密码认证依据分别记录（verificationBasis 不再把密码认证记成 google_auth）。

## 六、顺带修复的真实回归（本轮改动引入，由浏览器回归发现）

1. `useCommands` 读写未隔离的 `["workspace"]` 缓存键 → 命令结果不回写用户视图（步骤不推进）；已改用 `scopedWorkspaceKey(userId)`。
2. 工作区加载 Promise 无兜底 → 偶发拒绝时 UI 永久停在加载占位；已改为可恢复回退并记录错误。
3. 768px 顶栏横向溢出（新增语言控件/演示选择器挤压）；已按断点收起次要控件。
4. 测试设施：按用户隔离的夹具写入、水合等待、登录夹具（门禁下 UX 回归需 active 会话）。

## 七、剩余限制 / 仍需外部配置

1. **E21 真实邮件未联调**：需部署负责人提供可用 SMTP/事务邮件服务与允许使用的发件身份（配置字段：`MAIL_MODE=smtp、SMTP_HOST、SMTP_PORT、SMTP_USER、SMTP_PASSWORD、SMTP_TLS_MODE(starttls|implicit|none)、MAIL_FROM`；TLS 证书/主机名校验、域名认证按提供方指引）。安全配置方法：密钥仅放部署环境/密钥管理服务，不进 Git；建议先向受控测试收件人发送验证模板，再核对学校收件过滤。捕获器测试不宣称真实收件成功。
2. **真实 Google 联调**（R3）：`GOOGLE_CLIENT_ID/SECRET/REDIRECT_URI` + 控制台回调登记（回调须回到公开站点）；能力开关已就绪（未配置时入口隐藏，不影响邮箱通道）。
3. **R2**：学校邮件/教师审核真实联调；业务模块服务端持久化与逐接口资源授权（`services/business.py` 边界未变）。
4. **R3**：业务页面三语文案批次（439 键已覆盖入口/账户/认证/核心页）；受控账户关联（Google↔密码）设计；密码策略按学校安全要求收紧。
