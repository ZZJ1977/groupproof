# 阶段 02 总结：版本模型与成员确认

日期：2026-10-06 · 状态：待验收 · 完整记录见[阶段总览](../README.md#阶段实施记录)

## 任务范围

建立不可变正式版本、独立草稿、按版本绑定的成员确认和兼容旧浏览器数据的迁移模型，供阶段 03 命令层与后续业务阶段复用。

## 完成内容

- **类型**：`MemberConfirmation` / `Revision<T>` / `BaselinePayload` / `PlanPayload` / `BaselineRevision` / `PlanRevision` / `CourseRuleSnapshot` / `CourseRuleRevision` / `RuleChangeReview`；`MockData.schemaVersion` + 四个版本集合；`Project.activeBaselineRevisionId` 等血缘字段（含 `sourceProjectId`）。
- **版本核心**（`lib/versioning.ts`）：`migrateWorkspace` 增量迁移（幂等、不改输入、格式错误报告）；`buildLegacyRevisions` 为旧 frozen 基线/已确认计划/课程规则建立已发布历史快照（`legacy.confirmedUserIds` + `timestampUnknown`，不伪造时间）；确认辅助 `confirmMember`（幂等、绑定 revisionId+contentVersion）、`applyContentChange`（内容版本递增并清空确认）、`applyMemberRoster`（名单变化使旧确认失效）、`confirmationsComplete`；选择器 active/draft 版本读取。
- **存储**：mock-service 读取时迁移，原始记录备份到 `groupproof-v1-workspace-legacy-backup`；格式错误不覆盖原数据。
- **页面（08/09/10）**：版本页区分“当前正式版本”/“待确认草稿”，显示逐人确认状态与时间（历史确认标注未记录时间）；个人确认写入绑定版本的 MemberConfirmation。
- **测试**：`npm run check:versioning` 独立断言脚本。
