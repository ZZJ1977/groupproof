### 需要说明的设计决定

1. **每组只有一个项目**：创建时先锁小组记录再查，数据库唯一索引兜底；两个请求同时到达时，后到的那个得到 `PROJECT_ALREADY_EXISTS`。
2. **新项目带入的内容**：本组当前全部成员（组长角色跟小组一致）、课程截止日期（作为项目结束日期）、课程里程碑模板（按顺序建成里程碑）。数据库里原来没有“课程里程碑模板”，所以新建了模板表和老师用的接口；老师页面上的编辑入口不在本阶段范围内，目前只能通过接口设置。
3. **开始日期**：`projects` 表原来没有开始日期。为了不改动大家共用的 `projects` 表（C 的迁移兼容测试会用旧表结构写数据），开始日期放在 B 自己的 `b_project_schedules` 表；结束日期仍是 `projects.final_deadline`。
4. **总览进度**：直接调用 C 的 `progress_projection`（根任务加权），和 C 页面上的数字一致。任务树数据有问题时显示“任务结构异常”，不报错。
5. **文件资料**：只接受“本项目、本人上传、已完成”的上传回执；正文通过 `MaterialTextPort`（A4-05）取。A4-05 没接通时状态是“正文暂不可用”并写明原因，不存假正文。
6. **基线冻结后**基本信息和资料都不能再改（`BASELINE_FROZEN`），项目归档或课程结束后只读（`PROJECT_READ_ONLY`）。
7. 页面 08 的第 3–5 步（需求分析、冲突处理、基线确认）属于 B-4，现在按钮是灰的，写着“下一阶段开放”。
