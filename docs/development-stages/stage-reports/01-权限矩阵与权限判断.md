# 阶段 01 总结：权限矩阵与权限判断

日期：2026-10-06 · 状态：待验收 · 完整记录见[阶段总览](../README.md#阶段实施记录)

## 任务范围

建立“当前用户 × 目标资源 × 操作”的统一权限资格判断，供路由、页面和后续业务命令共用；账号角色、资源关系、执行条件分层。沿用现有 UI，覆盖 B 页面 07–10、23、29、35、38–40、46–47；个人资料与平台治理保持专用规则。

## 完成内容

- **权限核心**：新增 `lib/access/policy.ts`，只读纯函数 `can(data, actorId, action, target)` + `projectSummary` / `isCourseStaff`。组长按目标 `Group.leaderId` 或无小组项目 `ownerId` 判断；助教按 `Course.assistantGrants` 逐操作授权（默认只读）；未知操作、无效目标、跨课程引用、非 active 账号默认拒绝；管理员不默认获得本范围权限。
- **领域类型**：新增 `DelegatedPermission`、`AssistantGrant`、`ProjectSummary`；`Course.assistantGrants?`、`Project.ownerId?`。公开总览 DTO 仅含 id/name/description/progress/lifecycle。
- **演示数据**：独立助教 `ta-1`（归属 course-1）；`project-2.ownerId = member-1`；项目补充 `visibility`（project-1 为 course）。角色切换的 ta 不再复用 teacher-1。
- **页面接入**：`useProjectCore` 统一产出 canView/canSummary/canEdit/canLead；项目页按 summary.read/content.read 选择视图，仅有公开资格时展示公开总览组件（新增 `ProjectPublicSummary.tsx`）；B 写入口分别接 `project.files.write` / `settings.update` / `archive` / `create` / `rules.apply` / `reopen` / `course.settings.update` / `rules.edit` / `rules.publish`；RouteDispatcher 布局与资格分离，所属教学人员可进入项目页。
- **测试**：新增 `scripts/check-access.mjs`，`npm run check:access` 权限矩阵断言（53 项）。

## 剩余限制

- `can()` 仅判断资格；状态机、版本冲突、确认完整性由阶段 03 命令层拒绝。
- 非 B 模块写入口仍直接 CRUD（部分仍用全局角色标签），清单见[写入口迁移清单](../01-写入口迁移清单.md)。
- 助教授权授予/撤销命令待阶段 03/04；演示权限仍为前端门禁，不构成真实鉴权。
- 旧浏览器缓存需清空 `groupproof-v1-workspace` 才能看到新种子字段。
