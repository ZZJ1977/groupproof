### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/me/courses?tab=&q=&page=&page_size=` | 只返回自己当前加入的课程，含各 Tab 数量、每门课待处理数、等待审批中的申请 |
| GET | `/api/v1/me/courses/{course_id}` | 不是成员一律 404 |
| POST | `/api/v1/course-joins/preview` | 邀请码预览（用 POST，避免邀请码出现在网址和日志里） |
| POST | `/api/v1/course-joins` | 加入；必须带 `Idempotency-Key` |
| GET | `/api/v1/courses/{course_id}/join-requests` | 本课老师/助教查看申请 |
| POST | `/api/v1/course-joins/{id}/decision` | 本课老师批准/驳回，带 `expected_version` |
| GET/PUT | `/api/v1/courses/{course_id}/join-policy` | 本课老师设置加入方式（直接 / 审批） |

### 需要说明的设计决定

1. **加入方式**：课程表里没有“直接加入还是要审批”的设置（`grouping_mode` 管的是组队）。B 新建 `b_course_join_policies`，没有记录时按“直接加入”。如果以后课程规则（C）要统一管理这个设置，再改成读 C 的字段。
2. **“课程已关闭”的判断**：C 的 `resolve_course_invite` 对所有不可用的邀请码都返回同一个 404。为了让学生看到“课程已结束”，B 先查一次邀请码对应的课程，课程已结束时返回 `409 COURSE_CLOSED`；其余情况仍以 C 的结果为准。
3. **改了别人的测试**：`test_database.py`、`test_readiness.py`、`test_c_auth_migration_compatibility.py` 里写死了最新迁移号 `0017`，已改为 `0018`（加迁移时的常规调整）。
