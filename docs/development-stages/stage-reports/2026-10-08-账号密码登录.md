# 迭代总结：账号密码注册/登录窗口

日期：2026-10-08 · 需求：用户新增（在登录板块设置已注册账户登录窗口，用户名/邮箱 + 密码注册后登录，注册信息入库）· 状态：核心完成，遗留项见文末

> 决策变更记录：方案 v1.1 原定「保留 Google 为唯一身份认证入口，不另设密码注册系统」。按用户 2026-10-08 最新要求新增账号密码注册/登录，与 Google 并存；其余安全边界不变（方案文档已记录此变更）。

## 任务范围

登录页新增「已注册账户登录」窗口（用户名/邮箱 + 密码）与「注册账号」窗口（用户名 + 登录邮箱 + 密码）；注册信息持久化到 PostgreSQL；密码账户沿用同一注册闭环与会话/鉴权模型。

## 完成内容

- **数据库**：迁移 `server/migrations/versions/0002_password_credentials.py` 新增 `password_credentials`（user_id PK/FK、login_email_normalized UNIQUE、password_hash bcrypt、password_algo、password_changed_at）；与 Google 身份（auth_identities）分开管理，不自动合并账户。字段字典已更新。
- **后端接口**（`server/app/routers/auth.py`、`me.py`）：
  - `POST /api/v1/auth/password/register`：用户名/登录邮箱/密码注册；用户 + 凭据同事务创建（唯一约束兜底并发，失败整体回滚）；签发 onboarding 会话进入「资料 → 学校邮箱验证 → 教师审核」同一注册闭环；匿名 POST 做 Origin 校验。
  - `POST /api/v1/auth/password/login`：用户名（users.username_normalized）或登录邮箱（password_credentials.login_email_normalized）+ 密码；未知用户/错误密码统一 `INVALID_CREDENTIALS`（不泄露账户存在性）；服务端限流 5 次/15 分钟（按标识）、20 次/15 分钟（按 IP）；按账户状态签发 onboarding/full/status_only 会话。
  - `POST /api/v1/me/password`：改密需当前密码 + CSRF；密码策略 8–72 字节；只更新 bcrypt 哈希并轮换当前会话；审计不记明文。
- **密码安全**：bcrypt（cost 12）只存哈希（`security.py`：hash_password/verify_password/validate_password）；任何响应、日志、审计不含明文；`/me` 暴露 `passwordLoginEnabled` 标记（非凭据本体）。
- **前端**（`features/auth/LoginPage.tsx`）：登录卡片在 Google 入口下新增「已注册账户登录」窗口（用户名或邮箱 + 密码，防重复提交，失败保留输入就近提示）与「注册账号」Dialog（用户名/登录邮箱/密码/确认密码）；成功后按服务端 `nextAction` 引导（active 才优先进入 returnTo 业务页）；`lib/api/auth-client.ts` 增加 passwordLogin/passwordRegister/changePassword；个人中心资料页新增「修改密码」面板（无凭据账户显示说明）。
- **词条**：`auth.passwordLogin.*`、`auth.register.*`、`account.profile.password*`、`errors.INVALID_CREDENTIALS` 三语补齐（331 → 369 键）。

## 剩余限制 / 未联调

1. **密码找回/重置流程未做**（需要邮件通道；当前改密仅限本人登录后）。真实学校邮件联调仍缺 SMTP 凭据（同前次迭代）。
2. **未提供密码账户与 Google 账户的绑定/合并入口**：同一人可能持有两个独立账户；按既有规则不自动合并，受控换绑/合并流程待单独设计。
3. 登录邮箱与学校邮箱是两个字段：登录邮箱无域名限制（仅唯一），学校邮箱仍在个人中心按域名规则验证；如需限制登录邮箱域可收紧 `security.py`。
4. 真实浏览器 UI 走查（注册/登录窗口视觉与键盘流）仅覆盖 DOM/负面断言与 API 等价流程，完整交互截图待 `check:browser` 扩展用例。
